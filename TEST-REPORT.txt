ImageSlidePlugin 0.8.1 universal release verification
================================================================

Scope
-----
- One source tree and one plugin ZIP for Windows x64, macOS x64, and macOS arm64.
- Stable plugin/action UUIDs and preserved Windows helper files/behavior.
- macOS Setup is ProfilesV2-only and requires manual Studio reopen.
- Configurable localized date/time screen between images or as an exclusive clock-only display.
- Setup diagnostics and Windows Restore lineage remain bound across new pages and repeated cycles.
- Optional WeatherAPI current conditions and three-day forecast with bundled MIT Meteocons.
- Independent content controls, two-panel clock, CPU/GPU/RAM screen, and ordered due-panel queue.
- CPU/GPU/RAM sampling runs only while the system-resource panel is visible.
- The active Windows plugin was backed up and updated for physical validation; packaging did not modify the live profile or D200 state.
- Runtime sharp 0.35.5 with the delivered native targets, and a public source archive free of internal development records.

Release work units
------------------
1. Independent content rotation and system resources
   - Image/date/weather/system choices, legacy-only-mode migration, two-panel Lucide clock,
     CPU/GPU/RAM cards, information-only rotation, and ordered due-panel queuing.
   - Focused verification: Node source tests 59/59. Runtime boundary: physical Windows D200
     metrics, panel layouts, no-image rotation, and equal-frequency sequential order.
   - Rollback boundary: slideshow/system runtime, Inspector, Lucide license, docs, and tests.
2. WeatherAPI forecast display
   - Periodic and weather-only modes, three-day forecast, Celsius/Fahrenheit, localized labels,
     bounded HTTPS responses, stale-data fallback, request race protection, and flat PNG rendering.
   - Focused verification: Node source tests 54/54. Runtime boundary: physical Windows D200
     WeatherAPI data, Meteocons visibility, and final typography acceptance.
   - Rollback boundary: weather module/assets, slideshow/Inspector integration, docs, and tests.
3. Setup diagnostic and Restore lineage correction
   - Instance-bound failed diagnostics, safe legacy semantic normalization, center fingerprints,
     and deterministic priority for matching fingerprinted receipts across repeated cycles.
   - Focused verification: Node source tests 47/47. Runtime boundary: Windows D200
     new-page Setup and Restore -> Install -> Restore cycle.
   - Rollback boundary: Setup runtime, Windows/macOS helpers, migration notes, and their tests.
4. Localized date/time display
   - Periodic insertion with configurable image frequency and duration, continuous clock-only mode,
     localized weekday, system date/time conventions, and explicit date-order overrides.
   - Focused verification: Node source tests 47/47. Runtime boundary: physical Windows D200 acceptance.
   - Rollback boundary: slideshow runtime, Property Inspector, settings, documentation, and tests.
5. Universal platform contract and Setup hardening
   - Official `windows`/`mac` manifest and Store platform tokens, Darwin dispatch,
     ProfilesV2-only claims, manual reopen, and tested post-rename rollback.
   - Focused verification: Node source tests 45/45. Runtime boundary: temp-fixture helper lifecycle.
   - Rollback boundary: manifest/store metadata, macOS helper, setup dispatch, and their Node tests.
6. Reproducible universal packaging and delivery gates
   - Lock-integrity downloads, explicit target inventory, PE/Mach-O inspection, deterministic ZIPs,
     platform-aware Python tests, and Studio Node x64 decode harness.
   - Focused verification: stage PASS; Python final 30 passed/2 skipped; Studio Node harness PASS.
   - The optional production-shape Windows fixture is repository-relative by default and can be
   supplied with IMAGESLIDE_WINDOWS_PROFILE_FIXTURE and IMAGESLIDE_WINDOWS_PROFILE_ID; only
   fixture-dependent tests skip when either value is unavailable.
   - Delivery-wide privacy checks inspect standalone files plus every member of the plugin, source,
     helper, and profile archives. The portable profile receipt omits all source identity provenance.
   - The public source archive does not package the internal odd/ development records.
   - Rollback boundary: tools/profile_tool.py, tools/build_release.py, and tests/test_delivery.py.
7. Release documentation and local artifacts
   - README, MIGRATION, Store copy, TEST-REPORT, three ZIPs, and SHA256SUMS.
   - Focused verification: deterministic rebuild produced identical ZIP hashes; ZIP/checksum readback PASS.
   - Rollback boundary: documentation and generated local artifacts only.
8. Runtime security bump to sharp 0.35.5
   - sharp moved from 0.35.4 to 0.35.5 (librsvg 2.63.2) for CVE-2026-96889 / GHSA-wq5f-xc86-pv6w,
     with the lockfile, the builder runtime inventory, and every native target moved together.
   - The installer and the delivery suite no longer restate the sharp version. The installer reads it
     from the staged sharp package.json, and the suite derives the native member names from the
     builder runtime inventory. The libvips dylib name is discovered, because it follows the libvips
     version and not the npm package version.
   - Focused verification: Node source tests 59/59; Python suite 34 tests, 2 skipped; the rebuilt
     plugin ZIP was verified file-by-file against the staged tree (189/189 files); the Studio Node
     runtime decoded and cover-resized an SVG to 458 x 196.
   - Runtime boundary: accepted on a physical Windows D200 with image rotation, an SVG, clock/system
     panels, and Setup Large Display.
   - Rollback boundary: package and lock pins, builder runtime inventory, installer and suite
     assertions, README, MIGRATION, and TEST-REPORT.
9. Source archive privacy
   - The public source archive stopped packaging the internal odd/ development records, one of which
     carried a local development path and failed the delivery privacy scan.
   - Focused verification: source_files() yields no odd/ arcname; the rebuilt archive has 0 of 90
     members under odd/; the full delivery suite passes including the privacy scan.
   - Rollback boundary: tools/build_release.py source exclusions and tests/test_delivery.py.

Physical validation status and limitations
------------------------------------------
- macOS x64 slideshow import/decode and ProfilesV2 Setup/Restore have prior physical evidence.
- That prior local Studio evidence used an installed disposable manifest with `macos`; it was not
  modified. Source and release artifacts now use the official `mac` schema token.
- macOS clock overlay can remain visible; this is an accepted release-candidate limitation.
- macOS requires manual Studio reopen after Setup; relaunch is not implemented.
- Windows x64 installation, manual profile import, action discovery, slideshow rotation, and clock suppression passed on a physical D200.
- The installed 0.8.0 plus sharp 0.35.5 candidate was accepted on a physical D200 across image
  rotation, an SVG file (the path the librsvg advisory affected), clock/system panels, and Setup
  Large Display. That accepted build is byte-for-byte identical to the built plugin ZIP.
- Periodic date/time insertion, localized/system and explicit date formats, bold clock typography,
  and continuous date/time-only mode were accepted on the physical Windows D200.
- Periodic/weather-only modes, flat PNG Meteocons, three-day forecast cards, and final typography
  were accepted on the physical Windows D200.
- Independent content controls, two-panel Lucide clock, live CPU/GPU/RAM cards, information-only
  rotation, and date/weather/system due-panel sequencing were accepted on the physical Windows D200.
- Windows Setup accepted a physical Restore -> Install -> Restore cycle after Studio normalization.
- Windows automated verification passed 59/59 Node tests and the full available Python suite
  (34 tests, 2 skipped); the 2 skips are the production-shape profile tests whose optional external
  fixture was absent.
- macOS arm64 packages were statically validated only; Apple Silicon was not physically tested.
- The version string is also the Setup request version. The Setup acceptance above ran with the
  0.8.0 string; the Node suite covers cross-version request handling, so an on-device Setup
  re-confirmation on 0.8.1 remains the only surface without physical evidence.
- Authoritative artwork uses the visually approved crop-safe 1200 x 630 JPEG cover with central safe margins and a 3:2 PNG banner.
- Publication and upload occur only after this report, the clean artifacts, and their checksums pass.
